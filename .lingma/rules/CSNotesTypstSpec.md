## Typst 语法规范

Typst 语法和模版组件的使用请参考 `99-索引与模板/TypstTemplate/example.typ`，它是一个完整的示例文件。尤其请注意开头对 AI 的提示。

### 核心语法规则

1. **数学变量加引号**：多字母变量必须用引号包裹，避免被识别为关键字
   - ✅ `$"length"$`, `$"parent"(i)$`, `$O("log n")$`
   - ❌ `$length$`, `$parent(i)$`, `$O(log n)$`
   - 单字母变量无需引号：`$x$`, `$n$`, `$a$`

2. **标题层级**：使用 `=` 符号，最多六级
   - `=` 一级（Part）, `==` 二级（Section）, `===` 三级（Subsection）
   - `====` 四级：用于并列知识点（内容较多、不适合用一般的有序无序列表时）
   - 五级和六级标题通常用“教程”、“步骤”类，比如说SpringCloud网关的快速完整的配置步骤等等
   - 建议实际使用不超过四级

3. **强调语法**：
   - 加粗：`*文本*`（单个星号，非 Markdown 的双星号）
   - 强调：`#emphasis[文本]`（主题色 + 圆体，用于关键句）
   - 关键词用加粗，关键句用强调

4. **注解符号处理**：Java/Spring 注解在标题或正文中需用 `#text()` 包裹
   - ✅ `=== #text("@Valid")：启用校验`
   - ❌ `=== @Valid：启用校验`（会被识别为标签引用）

### 常用组件

- **表格**：`#tex-table(...)`（TeX风格，仅水平线）或 `#plain-table(...)`（完整网格，通常用于第一行和第一列都需要强调的情况）
- **代码块**：使用标准 Markdown 三反引号，支持 30+ 语言
- **行内代码**：单反引号 `` `code` ``
- **提示框**：`#note[]`, `#tip[]`, `#warning[]`, `#caution[]`, `#danger[]`, `#info[]`, `#todo[]`
- **终端命令**：`#terminal[命令]`
- **分隔线**：`#fancy-divider`


### 关于目录

**目录结构层级**：

1. **Part（一级）**：使用 `#part("名称")`，表示大的主题模块
2. **Chapter（二级）**：在 `.typ` 文件中使用 `= 章节名`，表示具体章节
3. **Section（三级）**：使用 `== 节名`，表示章节内的主要知识点
4. **SubSection（四级及以下）**：使用 `===`、`====` 等，组织详细内容（**不会出现在目录草稿中**）

**目录草稿位置**：

- `main.typ` 文件中的注释通常作为目录草稿
- 格式示例：
  ```typst
  #part("主题名称")
  // % Chapter 1: 章节名
  // % == Section 1.1: 节名
  // % == Section 1.2: 节名
  ```

**编写原则**：

1. **优先参考现有目录**：如果 `main.typ` 中已有目录草稿，严格按照其结构编写
2. **保持层级一致**：确保 Part → Chapter → Section 的逻辑递进关系清晰
3. **文件组织灵活**：
   - 一个 `.typ` 文件可以包含多个 Chapter
   - 相关 Chapter 可以放在同一个文件中
   - 不要擅自创建或删除文件，除非用户明确要求
4. **目录优化建议**：
   - 如果发现目录结构不合理，可以先提出优化建议
   - 等待用户确认后再进行调整
   - 优化原则：合并过细的 Section，拆分过大的 Chapter
5. **领域解耦原则**：
   - 编程语言笔记专注于语言自身的 API、特性和实现
   - 基础理论知识（如网络协议、操作系统原理、算法理论等）应在对应的专业笔记中体现
   - 除非真的有必要，否则不引入跨领域的基础概念
   - 示例：Java 网络编程笔记专注于 Socket/NIO/Netty API，不讲解 TCP/IP 协议细节（应在计网笔记中）

**典型结构示例**：

```
main.typ
├── #part("第一部分：基础")
│   ├── #include "chapters/基础概念.typ"
│   │   ├── = Chapter 1: 概述
│   │   │   ├── == 1.1 定义
│   │   │   ├── == 1.2 特点
│   │   │   └── == 1.3 应用场景
│   │   └── = Chapter 2: 核心原理
│   │       ├── == 2.1 工作机制
│   │       └── == 2.2 关键组件
│   └── #include "chapters/高级特性.typ"
│       └── = Chapter 3: 高级模式
│           ├── == 3.1 设计模式
│           └── == 3.2 最佳实践
└── #part("第二部分：实战")
    └── ...
```

### 示例代码偏好
如果有地方需要写一段示例代码且**没有指定使用哪种语言时**（当然，如果这份笔记就是主要讲解某种语言或和某种语言强关联，那就属于已经指定），请遵循：

- 数据结构相关的优先使用 C++ 作为示例语言
- 其他的**如果合适**推荐使用 Kotlin 作为示例语言

### 其他说明
用户一般不会要求直接补全一整个 Part 或一次性补全太多的内容，如果提出请及时提醒说明一次生成太多会导致超出上下文长度限制等问题，并按照你认为合理的建议进行分段生成。
