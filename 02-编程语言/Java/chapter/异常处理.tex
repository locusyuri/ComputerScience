\chapter{异常处理}

Java 中的异常处理机制与 C\# 基本一致，但具有更完善的异常体系结构。本章将详细介绍 Java 异常的分类、处理方式以及最佳实践。

\section{异常概述}

\subsection{基本语法结构}

Java 提供了 \textbf{try-catch-finally} 结构来捕获和处理异常：

\begin{codeblock}[Java]{ExceptionDemo.java}
try {
    // 需要进行异常捕获的代码块
    // 可能抛出异常的代码放在这里
} catch (Exception ex) {
    // 捕获异常信息，catch 可以存在多个，用于捕获不同异常
    ex.printStackTrace();
} finally {
    // 不管前面的代码块是否异常，finally 中的内容都会执行
    // 通常用于资源释放，如关闭流、连接等
}
\end{codeblock}

\subsection{非检查性异常（Unchecked Exception）}

非检查性异常是 \textbf{RuntimeException} 及其子类，编译器不会强制检查。这类异常通常由程序逻辑错误引起。

\begin{tblr}{
  colspec = {|l|p{10cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
异常类 & 描述 \\
ArithmeticException & 当出现异常的运算条件时抛出，例如整数 \textbf{"除以零"} \\
ArrayIndexOutOfBoundsException & 用非法索引访问数组时抛出，索引为负或大于等于数组大小 \\
ArrayStoreException & 试图将错误类型的对象存储到对象数组时抛出 \\
ClassCastException & 试图将对象强制转换为不是实例的子类时抛出 \\
IllegalArgumentException & 向方法传递了不合法或不正确的参数时抛出 \\
IllegalMonitorStateException & 线程试图等待对象的监视器但本身没有指定监视器 \\
IllegalStateException & 在非法或不适当的时间调用方法时产生信号 \\
IllegalThreadStateException & 线程没有处于请求操作所要求的适当状态时抛出 \\
IndexOutOfBoundsException & 排序索引超出范围时抛出（数组、字符串或向量） \\
NegativeArraySizeException & 应用程序试图创建大小为负的数组时抛出 \\
NullPointerException & 应用程序试图在需要对象的地方使用 \textbf{null} 时抛出 \\
NumberFormatException & 字符串不能转换为适当数值格式时抛出 \\
SecurityException & 由安全管理器抛出，表示存在安全侵犯 \\
StringIndexOutOfBoundsException & String 方法中索引为负或超出字符串大小 \\
UnsupportedOperationException & 当不支持请求的操作时抛出 \\
\end{tblr}

\note{%
\textbf{NullPointerException} 是 Java 开发中最常见的异常之一，通常发生在：
\begin{itemize}
  \item 调用 null 对象的属性或方法
  \item 访问 null 数组的元素
  \item 集合中添加 null 后再进行操作
\end{itemize}
}

\subsection{检查性异常（Checked Exception）}

检查性异常是 \textbf{Exception} 的子类（除 RuntimeException 外），编译器会强制检查，必须进行处理。

\begin{tblr}{
  colspec = {|l|p{10cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
异常类 & 描述 \\
ClassNotFoundException & 应用程序试图加载类时，找不到相应的类 \\
CloneNotSupportedException & 调用 Object 类的 clone 方法，但类未实现 Cloneable 接口 \\
IllegalAccessException & 拒绝访问一个类时抛出 \\
InstantiationException & 试图通过 Class 的 newInstance 创建抽象类或接口实例时抛出 \\
InterruptedException & 一个线程被另一个线程中断时抛出 \\
NoSuchFieldException & 请求的变量不存在 \\
NoSuchMethodException & 请求的方法不存在 \\
\end{tblr}

\warning{%
\textbf{必检异常（Checked Exception）} 意味着编译器会强制程序员检查并通过 try-catch 块处理它们，或者在方法头进行声明。这是 Java 与其他语言的重要区别。}

\section{Throwable 类方法}

\textbf{Throwable} 是 Java 语言中所有错误和异常的超类。理解其核心方法对于异常处理至关重要。

\begin{tblr}{
  colspec = {|c|p{11cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
序号 & 方法及说明 \\
1 & \textbf{public String getMessage()} \\
  & 返回关于异常的详细信息。这个消息在 Throwable 类的构造函数中初始化 \\
2 & \textbf{public Throwable getCause()} \\
  & 返回一个 Throwable 对象，代表异常原因 \\
3 & \textbf{public String toString()} \\
  & 返回此 Throwable 的简短描述（包含类名和 getMessage） \\
4 & \textbf{public void printStackTrace()} \\
  & 将此 Throwable 及其回溯打印到标准错误流 \\
5 & \textbf{public StackTraceElement[] getStackTrace()} \\
  & 返回包含堆栈层次的数组。下标为 0 的元素代表栈顶，最后一个代表方法调用栈的栈底 \\
6 & \textbf{public Throwable fillInStackTrace()} \\
  & 用当前的调用栈层次填充 Throwable 对象栈层次 \\
\end{tblr}

\begin{codeblock}[Java]{ThrowableMethods.java}
try {
    // 可能抛出异常的代码
} catch (Exception e) {
    // 获取异常详细信息
    System.out.println("异常信息: " + e.getMessage());
    
    // 获取异常原因
    Throwable cause = e.getCause();
    if (cause != null) {
        System.out.println("原始异常: " + cause.getMessage());
    }
    
    // 打印完整堆栈信息
    e.printStackTrace();
    
    // 获取堆栈数组进行分析
    StackTraceElement[] stackTrace = e.getStackTrace();
    for (StackTraceElement element : stackTrace) {
        System.out.println(element.getClassName() + "." + 
                          element.getMethodName() + "():" + 
                          element.getLineNumber());
    }
}
\end{codeblock}

\section{异常类型体系}

Java 的异常体系呈树形结构，所有异常都继承自 \textbf{Throwable} 类。

\begin{tblr}{
  colspec = {|l|p{7cm}|p{4.5cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
类型 & 描述 & 代表异常 \\
\textbf{Error} & 程序中无法处理的错误，表示严重的系统问题 & VirtualMachineError、OutOfMemoryError、StackOverflowError \\
\textbf{Exception} & 程序本身可以捕获并且可以处理的异常 & - \\
\end{tblr}

\subsection{Error（系统错误）}

\textbf{Error} 类描述的是内部系统错误，这类错误很少发生，通常由 JVM 抛出。

\begin{tblr}{
  colspec = {|l|p{8cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
类 & 可能引起异常的原因 \\
LinkageError & 一个类对另一个类有依赖性，但编译前者后后者进行了不兼容修改 \\
VirtualMachineError & Java 虚拟机崩溃或运行所必需的资源已经耗尽 \\
OutOfMemoryError & 内存耗尽（JVM 堆内存不足） \\
NoClassDefFoundError & 无法加载某个 Class（类路径配置错误） \\
StackOverflowError & 栈溢出（递归调用没有正确终止条件） \\
\end{tblr}

\caution{%
\textbf{Error 与 Exception 的关键区别}：
\begin{itemize}
  \item Error 通常是 JVM 层面的问题，程序无法恢复
  \item Exception 是程序逻辑问题，理论上可以捕获和处理
  \item 但实际开发中，不建议捕获 Error，因为无法有效恢复
\end{itemize}
}

\subsection{运行时异常（RuntimeException）}

\textbf{运行时异常}是程序设计错误，例如错误的类型转换、访问越界数组等。

\begin{tblr}{
  colspec = {|l|p{9cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
类 & 可能引起异常的原因 \\
ArithmeticException & 整数除以 0（注意：浮点数的算术运算不抛出异常） \\
NullPointerException & 试图通过 null 引用变量访问对象 \\
IndexOutOfBoundsException & 数组的下标超出范围 \\
IllegalArgumentException & 传递给方法的参数非法或不合适 \\
\end{tblr}

\note{%
\textbf{RuntimeException 的特殊性}：
\begin{itemize}
  \item \textbf{无需在 throws 子句中声明}，因为无法提前预防
  \item 此类异常在运行期间才能发现，一旦发生程序直接终止
  \item 体现了"快速失败"原则：发现问题后立即暴露，而不是隐藏
\end{itemize}
}

\emphasis{RuntimeException、Error 及其子类都称为免检异常（unchecked exception），编译器不会强制检查。所有其他异常（编译时异常）都称为必检异常（checked exception）。}

\section{异常处理方式}

\subsection{声明异常（throws）}

在 Java 中，方法必须声明它可能抛出的必检异常的类型，这称为\textbf{声明异常}。

\begin{codeblock}[Java]{ThrowsDeclaration.java}
// 声明可能抛出 IOException
public void readFile() throws IOException {
    // 方法实现
}

// 声明多个异常
public void process() throws IOException, SQLException {
    // 方法实现
}

// 重写方法中的 throws
class Parent {
    public void method() throws IOException {}
}

class Child extends Parent {
    @Override
    public void method() throws IOException {}  // 可以声明相同的异常
}
\end{codeblock}

\caution{%
\textbf{throws 声明规则}：
\begin{itemize}
  \item 如果方法没有在父类中声明异常，那么就不能在子类中对其进行继承来声明异常
  \item 子类重写方法可以抛出父类声明异常的子类，但不能抛出新的必检异常
  \item 如果父类方法没有声明异常，子类重写方法也不能声明必检异常
\end{itemize}
}

\subsection{抛出异常（throw）}

检测到错误的程序可以创建一个异常实例并抛出：

\begin{codeblock}[Java]{ThrowDemo.java}
// 抛出内置异常
public void validate(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("年龄不能为负数");
    }
}

// 抛出自定义异常
public void processOrder(Order order) {
    if (order == null) {
        throw new NullPointerException("订单对象不能为 null");
    }
}

// 直接抛出
throw new RuntimeException("这是一个运行时异常");
\end{codeblock}

\tip{%
\textbf{throw 与 throws 的区别}：
\begin{itemize}
  \item \textbf{throws}：用于方法声明，表示该方法可能抛出某些异常
  \item \textbf{throw}：用于实际抛出异常实例
\end{itemize}
}

\begin{warningbox}
\textbf{异常抛出后，try 块中 throw 之后的代码不会执行}。例如：
\begin{codeblock}[Java]{ThrowFlow.java}
try {
    throw new Exception("test");
    System.out.println("这段代码不会执行"); // 不可达代码
} catch (Exception e) {
    // 捕获处理
}
\end{codeblock}
\end{warningbox}

\section{try-catch-finally 详解}

\subsection{各部分职责}

\begin{itemize}
  \item \textbf{try 语句块}：放置可能出现问题的代码，尽量不要把不相关的代码放入其中
  \item \textbf{catch 语句块}：放置出现问题并捕获后的处理代码，如果 try 中没有问题发生则不会执行
  \item \textbf{finally 语句块}：放置不管异常是否产生都要执行的代码，通常用于资源释放
\end{itemize}

\subsection{多重 catch 块}

\begin{codeblock}[Java]{MultiCatchDemo.java}
try {
    // 可能抛出多种异常的代码
    String input = args[0];
    int num = Integer.parseInt(input);
    int result = 10 / num;
} catch (ArrayIndexOutOfBoundsException e) {
    // 处理数组越界
    System.out.println("请提供命令行参数");
} catch (NumberFormatException e) {
    // 处理数字格式错误
    System.out.println("参数必须是有效数字");
} catch (ArithmeticException e) {
    // 处理算术异常（如除以零）
    System.out.println("除数不能为零");
} catch (Exception e) {
    // 处理其他所有异常（通常放在最后）
    System.out.println("未知错误: " + e.getMessage());
} finally {
    // 资源清理代码
    System.out.println("无论如何都会执行");
}
\end{codeblock}

\begin{cautionbox}
\textbf{JDK 7+ 的 try-with-resources} 可以自动关闭资源，代码更简洁：
\begin{codeblock}[Java]{TryWithResources.java}
try (BufferedReader br = new BufferedReader(
        new FileReader("file.txt"));
     BufferedWriter bw = new BufferedWriter(
        new FileWriter("output.txt"))) {
    // 使用 br 和 bw 进行文件操作
    String line;
    while ((line = br.readLine()) != null) {
        bw.write(line);
        bw.newLine();
    }
} catch (IOException e) {
    e.printStackTrace();
}
\end{codeblock}
\end{cautionbox}

\section{finally 执行时机}

finally 块的执行时机非常明确，但有几种特殊情况需要注意。

\subsection{基本执行规则}

\begin{tblr}{
  colspec = {|l|p{10cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
场景 & 执行顺序 \\
正常执行 & try 块代码无异常执行完毕 → finally 块 → 方法继续执行后续代码 \\
异常捕获 & try 块抛出异常 → 匹配 catch 块处理 → finally 块 → 方法继续执行后续代码 \\
异常未捕获 & try 块抛出异常且无匹配 catch → finally 块 → 异常向上层调用栈抛出 \\
return 场景 & try 或 catch 块中 return，finally 会在 return 之前执行 \\
\end{tblr}

\subsection{return 与 finally 的交互}

\begin{codeblock}[Java]{FinallyReturn.java}
// 情况 1：try 中有 return，finally 中无 return
public static int test1() {
    try {
        return 1;  // 步骤1：保存返回值 1
    } finally {
        System.out.println("finally 执行");  // 步骤2：执行 finally
    }
    // 步骤3：返回保存的 1
}
// 输出：finally 执行，返回 1

// 情况 2：try 中有 return，finally 中也有 return
public static int test2() {
    try {
        return 1;
    } finally {
        return 2;  // 覆盖 try 中的返回值
    }
}
// 返回 2（这是不良实践，会导致原始返回值丢失）

// 情况 3：finally 中修改返回值 - 基本类型
public static int test3() {
    int i = 0;
    try {
        i = 1;
        return i;  // 保存返回值 1
    } finally {
        i = 2;  // 修改 i 的值，但返回的是之前保存的 1
    }
}
// 返回 1

// 情况 4：finally 中修改返回值 - 引用类型
public static List<String> test4() {
    List<String> list = new ArrayList<>();
    try {
        list.add("a");
        return list;  // 返回引用
    } finally {
        list.add("b");  // 修改引用指向的对象
    }
}
// 返回的 list 包含 ["a", "b"]
\end{codeblock}

\note{%
\textbf{返回值保存机制}：
\begin{itemize}
  \item 基本类型：return 时会复制值，finally 中的修改不影响已保存的返回值
  \item 引用类型：return 时保存的是引用，finally 中修改对象内容会影响最终返回结果
\end{itemize}
}

\subsection{finally 不执行的特殊情况}

\begin{tblr}{
  colspec = {|l|p{10cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
情况 & 说明 \\
System.exit() & JVM 正常退出，finally 块不会执行 \\
线程被杀死 & Thread.stop()（已废弃）或 Thread.interrupt() 未正确处理 \\
死循环/无限阻塞 & finally 块中存在无法完成的代码 \\
严重错误 & JVM 崩溃、内存溢出等，finally 可能无法执行 \\
\end{tblr}

\warning{%
虽然 finally 块\textbf{通常}会执行，但在生产环境中应避免依赖其进行关键操作。如果 finally 中的代码抛出异常，会覆盖原始异常。}

\section{自定义异常}

在实际开发中，Java 内置的异常类可能无法满足业务需求，需要自定义异常类。

\subsection{基本自定义异常}

\begin{codeblock}[Java]{MyException.java}
// 自定义检查性异常
public class MyException extends Exception {
    public MyException() {
        super();
    }
    
    public MyException(String message) {
        super(message);
    }
    
    public MyException(String message, Throwable cause) {
        super(message, cause);
    }
}

// 自定义运行时异常
public class BusinessException extends RuntimeException {
    public BusinessException() {
        super();
    }
    
    public BusinessException(String message) {
        super(message);
    }
    
    public BusinessException(String message, Throwable cause) {
        super(message, cause);
    }
}
\end{codeblock}

\subsection{自定义异常的使用示例}

\begin{codeblock}[Java]{CustomExceptionDemo.java}
public class OrderService {
    
    public void processOrder(Order order) throws MyException {
        try {
            // 验证订单
            if (order == null) {
                throw new MyException("订单对象不能为空");
            }
            if (order.getAmount() < 0) {
                throw new MyException("订单金额不能为负数");
            }
            
            // 处理订单逻辑
            orderRepository.save(order);
            
        } catch (MyException e) {
            // 记录日志或重新抛出
            logger.error("订单处理失败: " + e.getMessage());
            throw e;
        }
    }
}

// 调用示例
try {
    orderService.processOrder(order);
} catch (MyException e) {
    System.out.println(e.getMessage());  // 输出: 订单金额不能为负数
    System.out.println("异常捕获结束！");
}
\end{codeblock}

\tip{%
\textbf{自定义异常命名规范}：
\begin{itemize}
  \item 以 Exception 结尾：表示这是一个异常类
  \item 以业务名称开头：如 UserException、OrderException、BusinessException
  \item 根据类型选择父类：需要声明的使用 Exception，不需要的使用 RuntimeException
\end{itemize}
}

\section{异常处理最佳实践}

\subsection{异常处理原则}

\begin{enumerate}
  \itemsep=0pt
  \item \textbf{不要捕获所有异常}：只捕获可以合理处理的异常
  \item \textbf{不要吞掉异常}：至少要记录日志或重新抛出
  \item \textbf{不要使用异常控制流程}：异常用于异常情况，不用于正常逻辑
  \item \textbf{优先使用具体异常类型}：避免使用通用的 Exception 或 Throwable
  \item \textbf{释放资源时使用 finally 或 try-with-resources}
\end{enumerate}

\subsection{反模式示例}

\begin{codeblock}[Java]{AntiPatterns.java}
// 反模式 1：捕获所有异常并忽略
try {
    doSomething();
} catch (Exception e) {
    // 不要这样做！异常被完全忽略
}

// 反模式 2：使用异常控制流程
try {
    while (true) {
        // 如果数组遍历完毕会抛出异常
        list.remove(list.size() - 1);
    }
} catch (IndexOutOfBoundsException e) {
    // 退出循环
}

// 反模式 3：捕获后再抛出，丢失堆栈信息
try {
    doSomething();
} catch (IOException e) {
    throw new RuntimeException(e.getMessage());  // 错误：丢失原始堆栈
}

// 正确做法
try {
    doSomething();
} catch (IOException e) {
    throw new RuntimeException(e);  // 正确：保留原始异常
}
\end{codeblock}

\note{%
\textbf{异常链（Exception Chaining）}：当捕获一个异常后抛出另一个新异常时，应该将原始异常作为新异常的原因传递，这样可以保留完整的异常信息。}

\section{面试重点}

\subsection{checked exception 与 unchecked exception 的区别}

\begin{tblr}{
  colspec = {|l|p{7cm}|p{5cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
区别点 & 检查性异常 (Checked) & 非检查性异常 (Unchecked) \\
父类 & Exception（除 RuntimeException） & RuntimeException、Error \\
编译器检查 & \textbf{强制检查}，必须处理或声明 & 不检查，编译器不强制 \\
处理方式 & 必须使用 try-catch 或 throws 声明 & 可以选择处理或不处理 \\
典型场景 & IOException、SQLException、ClassNotFoundException & NullPointerException、ArrayIndexOutOfBoundsException \\
设计意图 & 程序可以恢复的异常情况 & 编程错误，通常表示 bug \\
\end{tblr}

\emphasis{从 Java 设计的角度来看，checked exception 体现了"编译时安全"的思想，要求开发者必须显式处理可预见的异常情况。}

\subsection{try-catch-finally 执行顺序}

\textbf{核心结论}：finally 块\textbf{总是会执行}，除非 JVM 退出。

\begin{codeblock}[Java]{ExecutionOrder.java}
public class ExecutionOrder {
    
    public static void main(String[] args) {
        System.out.println(test());  // 输出：finally 2
    }
    
    public static int test() {
        try {
            System.out.println("try");
            return 1;
        } catch (Exception e) {
            System.out.println("catch");
            return 2;
        } finally {
            System.out.println("finally");
            // finally 中的 return 会覆盖 try/catch 的返回值
            return 3;
        }
    }
}
\end{codeblock}

\warning{%
\textbf{面试高频问题}：
\begin{itemize}
  \item try 中有 return，finally 会不会执行？—— 会，在 return 之前执行
  \item try/catch/finally 都有 return，最终返回哪个？—— finally 的 return 覆盖其他
  \item 如果 finally 中修改返回值，基本类型和引用类型有何不同？—— 基本类型不生效，引用类型生效
\end{itemize}
}

\subsection{throw 与 throws 的区别}

\begin{tblr}{
  colspec = {|l|p{7cm}|p{5cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
区别点 & throw & throws \\
作用位置 & 方法内部使用 & 方法签名处使用 \\
含义 & \textbf{抛出}一个具体的异常对象 & \textbf{声明}方法可能抛出的异常类型 \\
数量 & 一次只能抛出一个异常 & 可以声明多个异常类型 \\
类型 & 抛出的是 Throwable 或其子类实例 & 声明的是异常类型（类名） \\
\end{tblr}

\begin{codeblock}[Java]{ThrowVsThrows.java}
// throws 用于方法声明
public void readFile() throws IOException, SQLException {
    // ...
}

// throw 用于抛出具体异常
public void validate(String input) {
    if (input == null) {
        throw new IllegalArgumentException("输入不能为空");
    }
}
\end{codeblock}

\subsection{finally 中 return 的问题}

\textbf{强烈不推荐在 finally 块中 return}，原因如下：

\begin{codeblock}[Java]{FinallyReturnProblem.java}
// 问题示例：异常被吞掉
public boolean test() {
    try {
        throw new RuntimeException("原始异常");
    } finally {
        return true;  // 原始异常被丢弃，无法被外层捕获
    }
}

// 调用方无法知道发生了什么异常
try {
    obj.test();  // 这里不会抛出异常！
} catch (RuntimeException e) {
    // 永远不会执行到这里
}
\end{codeblock}

\caution{%
\textbf{finally 中 return 是极差的做法}：
\begin{itemize}
  \item 会丢失 try/catch 中抛出的异常
  \item 违反"异常传播"原则
  \item 使代码难以调试和维护
\end{itemize}
}

\subsection{异常处理与性能}

异常处理有一定的性能开销：

\begin{tblr}{
  colspec = {|l|p{10cm}|},
  row{1} = {font=\bfseries},
  hlines,
  vlines,
  hline{1} = {0.8pt}
}
场景 & 说明 \\
正常流程 & 无明显性能影响，异常处理只是注册处理器 \\
异常发生 & 创建异常对象（需要获取堆栈快照）、查找处理器的开销较大 \\
StackTrace & getStackTrace() 或 printStackTrace() 会获取完整堆栈，开销较大 \\
高频异常 & 如果异常频繁发生，性能影响显著，应考虑使用返回值或状态码 \\
\end{tblr}

\emphasis{异常应该用于\textbf{异常情况}，不要用于正常流程控制。如果一个异常频繁发生，说明设计可能有问题。}
