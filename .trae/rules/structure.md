## 目录结构与文件组织规范

### 目录层级定义

1. **Part（一级）**：使用 `#part("名称")`，表示大的主题模块
2. **Chapter（二级）**：在 `.typ` 文件中使用 `= 章节名`
3. **Section（三级）**：使用 `== 节名`，章节内主要知识点
4. **SubSection（四级及以下）**：使用 `===`、`====` 等（不出现在目录草稿中）

### 目录草稿

- 位于 `main.typ` 文件中的注释
- 格式：
  ```typst
  #part("主题名称")
  //  Chapter 1: 章节名
  //  Section 1.1: 节名
  //  Section 1.2: 节名
  ```

### 编写原则

1. **优先参考现有目录**：如果 `main.typ` 中已有目录草稿，严格按其结构编写
2. **保持层级一致**：确保 Part → Chapter → Section 的递进关系清晰
3. **文件组织灵活**：
   - 一个 `.typ` 文件可包含多个 Chapter
   - 相关 Chapter 可放在同个文件中
   - 不创建或删除文件，除非明确要求
4. **目录优化建议**：
   - 发现目录结构不合理时，先提出建议
   - 等待用户确认后再调整
   - 原则：合并过细的 Section，拆分过大的 Chapter
5. **领域解耦原则**：
   - 编程语言笔记专注于自身的 API、特性和实现
   - 基础知识（网络协议、OS 原理、算法理论等）应在对应笔记中体现
   - 非必要不引入跨领域的基础概念
   - 示例：Java 网络编程专注于 Socket/NIO/Netty API，不讲 TCP/IP 细节（应在计网笔记中）

### 章节组织

- 逻辑清晰，层次分明
- 从基础到进阶逐步深入
- 相关内容归类到同一章节

### 列表与表格

- 无序列表使用 `-`
- 有序列表使用 `1.`
- 表格用于对比数据（如算法复杂度对比），表头清晰
