\ssection{标题层级示例}
模板提供了七层标题体系，其中 \texttt{chapter}、\texttt{section}、\texttt{ssection}、\texttt{sssction}、\texttt{paragraph} 和 \texttt{subparagraph} 分别对应不同的视觉层级。实际写作时，建议把 \texttt{chapter} 用作主题分区，把 \texttt{section} 用作核心小节，再根据内容密度向下拆分。

\ssection{正文与强调}
正文默认使用统一的中文字体和适中的行距。需要重点强调时，建议优先使用 \emphasis{强调样式用于句子级别的表达}，而不是手动切换大量字体命令。对于需要视觉聚焦的专业术语首次出现时，可使用 \highlight{服务注册与发现}、\highlight{负载均衡} 这类高亮方式，后续重复出现时则恢复普通文本或使用加粗。

路径和文件名可以用 \file{src/main/java/App.java} 这样的方式标识，终端命令可用 \terminal{mvn clean package} 来显示。若只是想突出一个词，例如“\textbf{同步}”、“\textbf{异步}”或“\textbf{只读}”，更适合直接用加粗。

\section{数学公式}
集合框架里经常会涉及复杂度分析。比如，哈希表平均查找复杂度接近 $O(1)$，红黑树查找复杂度通常为 $O(\log n)$。在实际笔记中，公式常用于说明“为什么这样选集合”，而不仅仅是展示符号本身。

\begin{equation}
  T(n) = T\left(\frac{n}{2}\right) + O(1)
\end{equation}

\begin{align}
  O(1) &< O(\log n) < O(n) \\
  O(n \log n) &< O(n^2)
\end{align}

\begin{equation*}
  \text{负载因子} = \frac{\text{元素数量}}{\text{数组容量}}
\end{equation*}

\subsection{问题描述}
在 Java 中，集合框架的选择通常由四个维度决定：是否允许重复、是否需要顺序、是否需要随机访问、是否线程安全。若还要放到更接近工程实践的视角下看，通常还要考虑数据量大小、并发读写比例，以及后续是否需要排序或范围查询。

例如，在分布式系统里，一个注册中心常涉及 \highlight{服务注册与发现}；一个网关或客户端侧组件则经常涉及 \highlight{负载均衡}。这些场景都会影响你选择 Map、Set 还是队列结构。

\subsection{结论归纳}
\begin{itemize}
  \item 如果强调随机访问，优先考虑 \textbf{ArrayList}。
  \item 如果强调去重，优先考虑 \textbf{HashSet}。
  \item 如果强调排序，优先考虑 \textbf{TreeMap} 或 \textbf{TreeSet}。
  \item 如果强调并发访问，优先考虑 \textbf{ConcurrentHashMap}。
\end{itemize}

\subsection{补充说明}
当需要强调某个关键结论时，可以写成：\emphasis{遍历中修改普通集合，应优先使用迭代器自身的删除方法，因为这能避免快速失败带来的异常。}
